## 3. Authentication & Authorization

### Security Configuration

- Class: `SecurityConfig`
- Package: `com.harsh.propertymanagementsystem.auth.security`
- CSRF: disabled
- Session policy: `SessionCreationPolicy.STATELESS`
- CORS:
  - Allowed origins: `http://localhost:5173`
  - Allowed methods: `GET`, `POST`, `PUT`, `DELETE`, `OPTIONS`
  - Allowed headers: `*`
  - Credentials: `true`
- Public URL patterns:
  - `/auth/**`
  - `/swagger-ui/**`
  - `/swagger-ui.html`
  - `/v3/api-docs/**`
- All other URL patterns: authenticated
- JWT filter: `JwtAuthenticationFilter` is added before `UsernamePasswordAuthenticationFilter`.
- Password encoder: `BCryptPasswordEncoder`

### JWT Details

- Class: `JwtService`
- Token subject: authenticated user's username, which is the user's email.
- Signing key: `jwt.secret` from `application.properties`
- Expiration: `jwt.expiration=900000` milliseconds
- Authorization header expected by filter: `Authorization`
- Header format: `Bearer <token>`
- Token validation:
  - Extracts username from token subject.
  - Loads user by email through `CustomUserDetailsService`.
  - Valid if username equals `UserDetails.getUsername()` and token is not expired.
- Invalid/expired JWT handling in `JwtAuthenticationFilter`:

```json
{
  "error": "Invalid or expired token"
}
```

- Invalid/expired JWT HTTP status: `401`

### Roles and Authorities

- Enum: `Role`
- Values:
  - `TENANT`
  - `OWNER`
- Authority format from `CustomUserDetails.getAuthorities()`:
  - `ROLE_TENANT`
  - `ROLE_OWNER`
- Registration assigns every new user role `TENANT`.
- Source contains no endpoint that registers an `OWNER`.
- Source contains no role-based endpoint annotations.

### Authentication Endpoints

#### Register

```text
HTTP Method: POST
URL: /auth/register
Authentication: Public because /auth/** is permitAll
Request: RegisterRequest
Response: RegisterResponce
Possible errors: EmailAlreadyExistsException, PhoneAlreadyExistsException, validation errors if validation annotations exist
```

Request JSON:

```json
{
  "firstName": "string",
  "lastName": "string",
  "email": "string",
  "phoneNumber": "string",
  "password": "string"
}
```

Response JSON:

```json
{
  "msg": "User Registeration Success"
}
```

Behavior:

- Checks `UserRepository.existsByEmail(request.getEmail())`.
- Throws `EmailAlreadyExistsException` with message `Email Already Exists` when email already exists.
- Checks `UserRepository.existsByPhoneNumber(request.getPhoneNumber())`.
- Throws `PhoneAlreadyExistsException` with message `Phone Already Exists` when phone already exists.
- Saves `User` with encoded password, `Role.TENANT`, `accountLocked=false`, `enabled=true`.
- `RegisterRequest` has `@Valid` in controller, but fields have no validation annotations in source.
- Specific exception handlers for `EmailAlreadyExistsException` and `PhoneAlreadyExistsException`: UNKNOWN — NOT FOUND IN SOURCE. They are checked exceptions and may fall through to the generic exception handler.

#### Login

```text
HTTP Method: POST
URL: /auth/login
Authentication: Public because /auth/** is permitAll
Request: LoginRequest
Response: raw JWT string
Possible errors: Authentication failure handling is UNKNOWN — NOT FOUND IN SOURCE
```

Request JSON:

```json
{
  "email": "string",
  "password": "string"
}
```

Response body:

```text
<jwt-token-string>
```

Behavior:

- Authenticates with `UsernamePasswordAuthenticationToken(request.getEmail(), request.getPassword())`.
- Generates a JWT using `JwtService.generateToken(userDetails)`.
- Returns the token directly as a `String`, not as a JSON object.

## 11. Frontend Integration Guide

### Authentication Flow

```text
Login with POST /auth/login
 ↓
Receive raw JWT string in response body
 ↓
Store token on frontend
 ↓
Send token as Authorization: Bearer <token>
 ↓
JwtAuthenticationFilter validates token
 ↓
SecurityContext current user is email from JWT subject
 ↓
Service methods load User by email and enforce ownership/tenant behavior
```

Registration flow:

```text
POST /auth/register
 ↓
Backend creates enabled, unlocked User with Role.TENANT
 ↓
Response contains {"msg":"User Registeration Success"}
```

### Endpoint Dependency

Verified backend dependency flow:

```text
Register User
 ↓
User row exists with id and Role.TENANT
 ↓
Login
 ↓
JWT
 ↓
Create Property with POST /properties
 ↓
propertyId from PropertyResponse.id
 ↓
Create Lease with POST /leases using propertyId and tenantId
 ↓
leaseId from LeaseResponse.id
 ↓
Tenant creates Payment with POST /payments using leaseId
 ↓
Payment endpoints and rent status use leaseId
```

Maintenance dependency flow:

```text
Create Property
 ↓
Create Lease for property
 ↓
Property status becomes OCCUPIED
 ↓
Tenant creates MaintenanceRequest with POST /maintenance using propertyId
 ↓
Owner updates status with PATCH /maintenance/{id}/status?status=<MaintenanceStatus>
```

Important frontend constraints from implementation:

- Login response is plain text JWT, not `{ "token": "..." }`.
- No endpoint returns the current authenticated user's profile.
- No endpoint lists all users or tenants.
- No endpoint lists properties.
- No endpoint retrieves property by ID.
- No endpoint updates or deletes properties.
- No endpoint creates owner users.
- Frontend must already know `tenantId` to create a lease; no source endpoint provides tenant lookup.
- Frontend must already know `propertyId` to create maintenance requests; only create property response returns a property ID.
